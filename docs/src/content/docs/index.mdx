## Why keep views in your own database?

A hosted analytics service tells you how your site is doing. It can't sort a query, fill a "readers also read" box or
know which of your users read what. Keeping views next to your models can.

|                                              | Eloquent Viewable                    | A hosted analytics service      |
|----------------------------------------------|--------------------------------------|---------------------------------|
| Order an Eloquent query by views             | `Post::orderByViews()`               | Export, import, keep in sync    |
| Show "trending" or "readers also read"       | One call                             | Build it on their API           |
| Count readers with an ad blocker             | Yes, recorded on your server         | Often blocked                   |
| Show a user what they viewed                 | `$user->viewed()`                    | Not linked to your users        |
| Where the data lives                         | Your database                        | Their servers                   |
| Funnels, sessions, referrer reports          | No                                   | Yes                             |

It is not a replacement for product analytics. It answers questions about your models, in the queries you already
write.

## Start simple, scale when you need to

Out of the box every view is one insert and every count is one query. When traffic grows, switch on the next step, one
config key at a time. None of them changes how you query.

<ScaleLadder />

## Works with your coding agent

The package ships guidelines and a skill for [Laravel Boost](https://laravel.com/docs/boost), so an agent records
and counts views the way these docs describe instead of guessing from older versions.

```bash
php artisan boost:update --discover
```

[Set up your coding agent](/eloquent-viewable/getting-started/ai-coding-assistants/)
