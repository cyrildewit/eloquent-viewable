# Security Policy

## Supported Versions

Security fixes are applied to the latest stable release. Older major
versions do not receive security updates, so we recommend staying on a
supported release.

| Version | Supported          |
| ------- | ------------------ |
| 8.x     | :white_check_mark: |
| < 8.0   | :x:                |

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub
issues, pull requests, or discussions.

Instead, report them privately through GitHub's built-in advisory flow:

1. Go to the [Security tab](https://github.com/cyrildewit/eloquent-viewable/security) of this repository.
2. Click **Report a vulnerability** to open a private advisory.
3. Fill in as much detail as you can (see below).

If you are unable to use GitHub's private reporting, you can reach the
maintainer at info@cyrildewit.nl.

### What to include

A good report helps us confirm and fix the issue faster. Where possible,
include:

- The affected version(s).
- A description of the vulnerability and its impact.
- Steps to reproduce, ideally with a minimal proof of concept.
- Any known workarounds.

## What to Expect

This is a community-maintained, open-source project. Reports are handled
on a best-effort basis, with no guaranteed response time and no
obligation to provide a fix. When time permits, we will try to:

- Acknowledge your report.
- Keep you informed as we investigate.
- Publish a release and, where warranted, a GitHub Security Advisory
  crediting your report (unless you prefer to stay anonymous).

If you do report an issue, please give us a reasonable amount of time to
respond before any public disclosure.

Nothing in this policy creates a warranty or legal obligation. The
software is provided "as is" under the [MIT License](LICENSE). Thank you
for helping keep this project and its users safe.
